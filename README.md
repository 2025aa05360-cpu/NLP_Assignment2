### Regenerating the dependency files

- **`requirements.txt`** is hand-curated: top-level packages only, with `>=` floors, grouped by
  purpose. Edit it whenever a new import is added to the notebook or the app. The floors are not
  arbitrary — e.g. `streamlit>=1.32` because the app uses `st.toggle`/`st.divider`, and
  `protobuf>=3.20` because the T5 SentencePiece → fast-tokenizer conversion needs it.
- **`requirements.lock.txt`** is generated. Run the _"Regenerate the dependency list"_ cell in
  Phase 0 of the notebook, or from a shell:

  ```bash
  pip freeze > requirements.lock.txt
  ```

  The notebook cell is preferred: it emits only the packages this project actually uses, so the
  file stays readable instead of listing ~200 transitive pins.

## 2. Train

Open the notebook and run every cell top to bottom:

```bash
jupyter lab GEC_T5_Assignment2.ipynb
```

What happens:

1. **Phase 1** downloads `grammarly/coedit`, keeps `task == 'gec'`, strips CoEdIT's embedded
   instruction, normalises and de-duplicates, injects 15% identity `(correct → correct)` pairs, and
   tokenizes with dynamic padding.
2. **Phase 2** fine-tunes `t5-small` with `lr=3e-4`, 6% warmup, batch 16, capped at 8 epochs.
   `EarlyStoppingCallback(early_stopping_patience=2)` on `eval_loss` stops training once validation
   loss has failed to improve for **2 consecutive epochs**, and `load_best_model_at_end=True`
   restores the best checkpoint.
3. The checkpoint is written to **`gec_t5_best/`** and zipped to `gec_t5_best.zip` by the packaging
   cell near the end.

To skip training entirely, just unzip the shipped checkpoint:

```bash
unzip gec_t5_best.zip
```

### What the app does

- Splits the input into sentences and corrects each one.
- Shows a colour-coded word-level diff (red = removed, green = inserted).
- Sidebar controls: beam size, **guard on/off**, max edit ratio, keep-original margin.
- An expander lists the guard's per-sentence decision, so over-correction can be demonstrated live
  by toggling the guard off on an already-correct sentence.

## Design notes

**Why only the `gec` subset of CoEdIT?** CoEdIT is a multi-task _editing_ corpus. Only `gec` rows
are grammar corrections; `clarity`, `coherence`, `simplification`, `neutralize` and `paraphrase`
rewrite text that is already grammatical. Training on all of them under one prefix teaches the
model that grammatical input should still be rewritten — exactly the over-correction failure mode
Phase 3 asks us to mitigate. The notebook prints the full task distribution before filtering.

**Over-correction is handled at three levels** (Phase 3):

1. _Data_ — 15% injected identity pairs make "copy the input" a high-probability action. The
   train/val/test split happens **before** augmentation and identity pairs are drawn from each
   split's own targets, so no-op inputs scored at evaluation were never seen in training.
2. _Decoding_ — reject candidates whose word-level edit ratio vs. the source exceeds `0.40`.
3. _Scoring_ — score the source itself as a decoder candidate; if
   `logP(source|source) >= logP(rewrite|source) − 0.05`, keep the original.

**Evaluation** (Phase 4): BERTScore against the reference (rescaled with the roberta-large baseline,
plus a copy baseline) for interpretability;
CER/WER in both directions (`pred → ref` = residual error, `src → pred` = how much the model
rewrote, compared against the gold edit rate); a no-op preservation rate that quantifies the guard;
and 5 success / 3 failure cases with diffs and an automatic failure classifier.
